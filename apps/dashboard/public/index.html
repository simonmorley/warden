#how-it-works

An AI can flag a phishing page in seconds.
When should it be allowed to block one?

Warden grants permission from reviewed results, limits unreviewed actions, and withdraws permission when an automatic block is confirmed wrong.

Live model calls. Simulated blocks. No websites are taken down.

Every automatic block is still reviewed. What changes is that the block happens before the review, not after — and no more than three can be waiting at once.

01

How permission is calculated

Warden uses the Wilson lower bound — a cautious estimate of precision that accounts for sample size. Under the default policy, 73 reviewed phishing verdicts with none wrong clear the 95% threshold. Mistakes require more evidence, and ten further correct checks in a row complete probation.

02

A verdict can't authorise itself

Whether a verdict acts is decided by arithmetic the model can't reach. A page can fool the classifier into a wrong verdict; it can't give itself permission.

Score a configuration

OFFLINE This screen qualifies the configuration. Is this model, prompt and policy good enough, on pages whose answers are known, to be worth deploying?
LIVE The live ledger qualifies the deployment. Whatever this screen says, the live system starts with no permission, and earns it from a person's judgements on real reports under Review. Nothing here grants it anything.

A set of pages whose real answers are already known, each classified by the live model and checked against that answer. The result is how often its phishing calls are right, with the range its true precision could plausibly fall in. Every verdict is a live model call, so nothing is scripted and the model does get some wrong. Takes two to three minutes; you can leave and come back, and refreshing keeps your place.
